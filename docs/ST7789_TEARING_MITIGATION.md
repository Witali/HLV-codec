# Уменьшение разрывов изображения ST7789 без вывода TE

## Исходные условия

Контроллер ST7789 поддерживает аппаратную синхронизацию записи с развёрткой:

- `TEON` (`0x35`) включает сигнал Tearing Effect на выводе `TE`;
- `TESCAN` (`0x44`) задаёт строку формирования сигнала `TE`;
- `GSCAN` (`0x45`) возвращает номер строки, которую дисплей сканирует в
  данный момент.

Команда `TEON` не устраняет разрывы самостоятельно. Процессор должен получить
сигнал с физического вывода `TE` и начать передачу изображения в подходящий
момент развёртки.

На ESP32-2432S028 вывод `TE` дисплея к ESP32 не подключён. Это видно на
[схеме дисплейного разъёма](board/ESP32-2432S028-schematic-LCM.jpg), а в
[`board_config.h`](../firmware/esp32_2432s028_hlv_player_idf_c/main/board_config.h)
такой GPIO отсутствует.

При этом линия чтения дисплея `TFT_MISO` подключена к `GPIO12`. Поэтому можно
синхронизироваться с развёрткой программно, читая текущую строку командой
`GSCAN` (`0x45`).

## Предлагаемый программный способ

1. Перед выводом кадра прочитать текущую строку ST7789 командой `0x45`.
2. Дождаться, пока развёртка выйдет из области экрана, которую предстоит
   обновить. Для полноэкранного кадра следует начинать передачу сразу после
   перехода развёртки через границу кадра. Для центрированного изображения
   можно ждать прохождения нижней границы обновляемой области.
3. Один раз задать прямоугольник командами `CASET` (`0x2A`) и `RASET`
   (`0x2B`).
4. Начать одну непрерывную запись `RAMWR` (`0x2C`).
5. Передавать последовательно подготовленные полосы `320 × 16` через два
   существующих DMA-буфера, не задавая окно заново между полосами и не
   прерывая поток пикселей.
6. Запомнить длительность передачи и номер строки в её начале и конце. Эти
   данные использовать для подбора наиболее безопасной точки запуска.

Текущая реализация вызывает `esp_lcd_panel_draw_bitmap()` отдельно для каждой
полосы. Каждый такой вызов может заново устанавливать окно и создавать паузу
между полосами. Для непрерывной записи потребуется передавать команды окна
один раз, затем ставить все полосы одного кадра в очередь как части одного
потока записи в GRAM.

## Проверка возможности чтения `GSCAN`

Сначала следует сделать небольшой диагностический тест:

1. Несколько раз за период обновления прочитать `0x45`.
2. Проверить, что возвращаемое значение меняется и находится в допустимом
   диапазоне строк контроллера.
3. Учесть предусмотренный протоколом фиктивный первый байт чтения.
4. Проверить соответствие направления счёта строк текущим настройкам
   `MADCTL`, повороту экрана и смещению видимой области.

Если `GSCAN` через установленный модуль или ESP-IDF-драйвер прочитать не
удастся, программная синхронизация по строке будет недоступна.

## Ограничения

- Это уменьшает вероятность разрыва, но не даёт такой же гарантии, как
  аппаратный сигнал `TE`.
- Передача должна укладываться в доступный временной интервал. При RGB565
  кадр `320 × 240` содержит 153 600 байт, а его теоретическое время передачи
  при SPI 80 МГц составляет около 15,36 мс без учёта команд и пауз.
- Если декодирование или подготовка полосы задержит непрерывный поток,
  развёртка может догнать область записи и разрыв снова станет видимым.
- У ST7789 нет команды переключения между двумя полными экранными буферами:
  `TE` и `GSCAN` только помогают синхронизировать запись во встроенную GRAM.

## Аппаратный вариант

Полностью управляемая синхронизация возможна, если дисплейный модуль физически
выводит сигнал `TE`. Тогда его можно подключить к свободному GPIO ESP32,
включить `TEON` в режиме вертикального гашения и запускать DMA-передачу по
прерыванию от фронта `TE`. Перед доработкой необходимо убедиться по распиновке
шлейфа или измерениям, что соответствующий контакт действительно доступен.
