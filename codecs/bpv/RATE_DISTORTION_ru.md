# Rate–distortion в BPV1

Экспериментальный модуль `src/bpv1-rate-distortion.js` выбирает запись
каждого блока 4×4 по критерию:

```text
J = D + λR
```

- `D` — точная RGB SSE по 16 пикселям блока;
- `R` — оценка переменной части записи: `SKIP=0`, `MOTION=8`,
  `BLOCK_DICT=16`, локальный `RAW=16/32/56` бит;
- фиксированные 2 бита карты режимов не учитываются, поскольку одинаковы для
  всех вариантов.

Кодировщик рассматривает несколько ближайших автоматически построенных BPAL-
палитр и блок с той же позиции предыдущего декодированного кадра. В стабильном
v6 после выбора выполняется точный поиск `SKIP`, блочного `MOTION` и словарных
ссылок.

Экспериментальный v7 (`--pixel-motion`) добавляет в тот же RD-поиск
попиксельные смещения `−7..+7`. Для каждого смещения кодировщик точно
моделирует декодер: читает RGB из предыдущего распакованного кадра и переводит
пиксели в ближайшие цвета выбранной палитры. Поэтому кандидат `MOTION` может
иметь ненулевую ошибку, но по-прежнему оценивается как `D + λ × 8`. Совпадение
палитр исходных блоков не требуется.

При `λ=0` выбирается минимальная ошибка среди кандидатов. Увеличение `λ`
разрешает небольшое ухудшение блока, когда это заметно уменьшает поток.

v6 остаётся форматом по умолчанию и не меняется. v7 не требует RGB-framebuffer
и не увеличивает постоянную память декодера, но поиск ближайших цветов делает
обработку `MOTION` вычислительно дороже.
